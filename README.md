## 📖 О проекте

### Зачем он нужен

Eatly — это не коммерческий продукт, а **тренировочная площадка**. Практическая цель проекта — набить руку на задачах, которые постоянно встречаются в реальной фронтенд-разработке, и собрать результат в законченную страницу, которую можно показать.

Проект помогает отработать:

| Направление | Что именно тренировалось |
|---|---|
| **Вёрстка** | Семантическая разметка (`header`, `main`, `section`, `article`, `footer`), БЭМ-именование, сложные сетки на Flexbox и CSS Grid |
| **Стили** | SCSS: `@use`/`@forward`, миксины, функции, переменные; CSS-переменные как дизайн-токены; псевдоэлементы, анимации |
| **Адаптивность** | Mobile-first, 4 брейкпоинта, fluid-типографика и отступы через `clamp()`, условное отображение элементов |
| **Работа с DOM** | Кастомные интерактивные компоненты: обработка событий, управление состоянием, классы состояния, атрибуты ARIA |
| **Доступность** | Клавиатурная навигация, роли и атрибуты ARIA, `visually-hidden`, осмысленные `alt` и подписи |
| **Сторонние библиотеки** | Интеграция и кастомизация Swiper |
| **Миграция на фреймворк** | Перенос императивного JS на декларативные React-компоненты и хуки, типизация на TypeScript |

### Как развивался проект

1. **Этап 1 — HTML + SCSS + vanilla JS.** Страница сверстана вручную, интерактивность написана на чистом JavaScript с классами (`Header`, `Select`, `ExpandableContent`) — чтобы понять, как DOM, события и состояние работают «под капотом», без фреймворка.
2. **Этап 2 — React + TypeScript.** Та же страница переписана на компоненты. Стили остались прежними, поэтому результат визуально идентичен, а разница видна именно в архитектуре кода: компоненты, хуки, типизированные данные вместо копирования разметки.

Такой путь удобен для обучения: сначала понимаешь, *что* делает браузер, а потом — *что* за тебя делает фреймворк.

## ✨ Что есть на странице

- **Header** — липкая шапка (`position: sticky`), которая при прокрутке получает тень; на мобильных превращается в компактную версию с бургер-меню.
- **Hero** — главный экран с призывом к действию, рейтингом и блоком метрик.
- **Advantages** — секция преимуществ с иллюстрацией.
- **Top Restaurants / Top Dishes** — каталоги карточек на адаптивных сетках (3 и 5 колонок, перестраиваются на планшетах и телефонах).
- **Dashboard (Purchases)** — список заказов, карточки статистики и кастомный выпадающий список периода.
- **Customer Say** — слайдер отзывов со сворачиваемыми длинными текстами.
- **Discount banner** — блок подписки с формой.
- **Footer** — навигация, копирайт и соцсети.

Ссылки в шапке и футере — якоря на секции страницы с плавной прокруткой.

## 🧩 Интерактивные компоненты

### 🔽 `Select` — кастомный выпадающий список
Полностью стилизованная замена нативного `<select>`:
- на десктопе — `combobox` с выпадающим `listbox`;
- на мобильных устройствах включается **нативный `<select>`** (удобнее для тач-экранов);
- управление с клавиатуры: `↑` `↓` — навигация, `Enter` / `Space` — открыть и выбрать;
- закрытие по клику вне списка;
- список открывается в сторону центра экрана, чтобы не выходить за край;
- ARIA: `role="combobox"`, `aria-expanded`, `aria-controls`, `aria-activedescendant`, `role="option"`, `aria-selected`.

### 🍔 `Header` — бургер-меню
- оверлей позиционируется относительно кнопки бургера;
- закрывается по клику вне меню, по крестику и автоматически при переходе на десктопную ширину (с debounce на `resize`).

### 📖 `ReviewCard` + `useExpandableContent` — «Read More / Roll Up»
- карточка становится сворачиваемой, только если текст длиннее порога;
- раскрытие и сворачивание анимируются через **Web Animations API** (`element.animate`);
- высота измеряется повторно после загрузки шрифтов.

### 🎠 Слайдер отзывов
- **Swiper** (`swiper/react`): зацикленная прокрутка, динамическая пагинация, разное число слайдов на разных ширинах.

## 🎨 Стили

Стили написаны на **SCSS** по методологии **БЭМ** и разложены по блокам:

```
src/styles/
  main.scss           # точка входа: подключает всё через @use
  _variables.scss     # CSS-переменные (цвета, шрифты, отступы, тени)
  _fonts.scss         # @font-face для Inter, Poppins, Manrope, Public Sans
  _globals.scss       # базовые стили и типографика
  _utils.scss         # утилитарные классы (.container, .visually-hidden, .hidden-mobile ...)
  helpers/            # функции rem() и fluid(), миксины, медиа-миксины
  blocks/
    header/  footer/
    home_page/        # стили конкретных секций
    shared_blocks/    # переиспользуемые блоки: button, card, grid, select ...
```

Что здесь стоит отметить:

- **Дизайн-токены через CSS-переменные:** цвета, шрифты, тени, длительность переходов лежат в `:root` и меняются в одном месте.
- **Fluid-типографика:** функция `fluid($max, $min)` генерирует `clamp()`, который плавно масштабирует размер между ширинами 390px и 1440px — без резких скачков на брейкпоинтах.
- **Единицы `rem`:** функция `rem()` переводит пиксели из макета в `rem`.
- **Медиа-миксины:** `laptop`, `tablet`, `mobile`, `mobile-s` (и их `*-above` версии) с синтаксисом диапазонов `(width <= …)`.
- **Миксин `hover`:** отдельно обрабатывает устройства с наведением и тач-устройства.
- **Scroll-driven анимации:** тень и граница шапки меняются в зависимости от прокрутки через `animation-timeline: scroll()`, без JavaScript.

### Брейкпоинты

| Название | Ширина | Где используется |
|---|---|---|
| `laptop` | ≤ 1440px | небольшие правки для ноутбуков |
| `tablet` | ≤ 1024px | планшеты: сетки и отступы уплотняются |
| `mobile` | ≤ 768px | телефоны: бургер-меню, колонки в одну линию |
| `mobile-s` | ≤ 481px | маленькие телефоны: шапка в две строки |

> Значения брейкпоинтов дублируются в `src/styles/helpers/_media.scss` и `src/constants/breakpoints.ts` — при изменении менять нужно оба места.

npm install

npm run build

npm run preview

## 📁 Структура проекта

```
site_eatly/
├── index.html                 # точка входа Vite
├── vite.config.ts
├── tsconfig*.json
├── _legacy/                   # старая версия (vanilla JS) — для сверки
└── src/
    ├── main.tsx               # монтирование React-приложения
    ├── App.tsx                # сборка страницы из секций
    ├── assets/                # fonts, icons, images
    ├── styles/                # SCSS
    ├── components/
    │   ├── layout/            # Header, Footer, Logo
    │   ├── sections/          # Hero, Advantages, Restaurants, Dishes, Purchases, Reviews, DiscountBanner
    │   ├── cards/             # RestaurantCard, DishCard, DishTile, StatisticCard, ReviewCard
    │   ├── ui/                # Select, LinkButton, Icon, RatingView, DivisionBadge, ...
    │   └── icons/             # инлайн-SVG как компоненты
    ├── hooks/                 # useMatchMedia, useExpandableContent
    ├── data/                  # типизированные данные (рестораны, блюда, отзывы, навигация ...)
    ├── types/                 # общие TypeScript-типы
    ├── constants/             # breakpoints
    └── utils/                 # cn, pxToRem
```

### Принципы организации кода

- **Данные отдельно от разметки.** Списки карточек лежат в `src/data` и описаны типами из `src/types` — добавить карточку значит добавить объект в массив, а не копировать блок разметки.
- **Переиспользуемые компоненты.** Кнопка-ссылка, рейтинг, бейдж, строка «время • оценка» вынесены в `components/ui`.
- **Логика в хуках.** Работа с `matchMedia` и раскрывающимся контентом вынесена из компонентов в `hooks`.
- **Стили не привязаны к React.** SCSS остался классическим БЭМ-набором, поэтому его можно использовать и без фреймворка.

## 🗂 Папка `_legacy`

Содержит оригинальную версию проекта до миграции: `index.html`, скрипты на vanilla JS (`Header.js`, `Select.js`, `ExpandableContent.js` и др.) и скомпилированный CSS. Она оставлена только для сравнения поведения — после проверки её можно удалить.
